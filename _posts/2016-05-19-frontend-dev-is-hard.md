Front end development is hard. Just consider all the things to need to know:

### Code

You need to know all the HTML tags, what they do, what their attributes are, when is it appropriate to use them, and how to structure your HTML with just the right amount of tags.

You need to know JavaScript, all the keywords, data types, a lot of patterns, the event loop, closures, promises, exceptions and error handling, logging, building/bundling, trans-piling, regular expressions, OOP, prototypes, strict mode, memory management, testing, test frameworks, and assertion libraries. You need to know literally every corner of jQuery, why its good, why its bad. You need to know lodash, mocha, should/chai, async (the library), and bluebird/when/q. You need to have a intimate knowledge of one and a working understanding of at three common frameworks including Backbone, AngularJS, React, Ember, Polymer, Knockout, Vue, and maybe even Meteor. You need to know es6 and how to run it in a browser and it wouldn't hurt to know a little coffee-script, TypeScript, and if you're a real badass ClojureScript. 

While we're on the subject, it wouldn't hurt to have experience writing Python, Ruby, Java, C#, C++, Go, and/or Scala (but all of those have equally complex ecosystem worthy of their own list rants).

You need to know CSS, and at least the two most popular preprocessors LESS and SASS. You need to know what all the CSS rules do, how to organize your CSS code, how the "cascade" works, id selectors, class selectors, attribute selectors, sibling selectors both adjacent and general, child selectors, descendant selectors, psuedo-classes, psuedo-elements, the box-model, CSS functions, transforms, transitions, animations, keyframes, media queries, font, font icons, and SVGs. And you need to know Bootstrap. 

### Environments

You need to know Chrome, Firefox, Safari, Edge, IE (at the very least down to IE8), Android, mobile safari. For all of these you need to know their supported features, debuggers, element inspectors, profilers, network inspectors, quirks (both literal and figurative), idiosyncrasies, inconsistencies, their DOM api, their BOM api. 

You need to know how to optimize for mobile, how to compress your production code, how to lazy load images, how to setup resource caching, and how to setup analytics.

You need to know NodeJS, async programming, file IO, Gulp, Grunt, Browserify, webpack, streams and vinyl, NPM, managing dependencies, shrinkwraping dependencies. If you are writing server code with node then you'll probably need to know Express or Hapi, handling requests, routing, cookies, templating using Jade/EJS/Nunjucks/Handlebars, connecting-to/reading-from/writing-to SQL/Mongo/Redis, clusters, HTTP, HTTP codes (at least the 10 most common ones), REST, JSON, and websockets.

### Tools

You need be proficient in one text editor and know its shortcuts, macros, snippets, packages (and a piece of advice, use it for literally everything). 

Git. Git. Git and any of the web-based git tools such as Github, BitBucket, and Stash. You need to know how to integrate your source control with automated testing, building, and deployment tools such as Jenkins, TravisCI, CircleCI. 

You may even need to know a little about cloud platforms such as Heroku, AWS, and Azure.

### People

You need to know how to work collaboratively, how to delegate work, how to properly document your code and projects, how to integrate your work into a bigger system, how to work with backend engineers, database engineers, test engineers, QA engineers, scrum masters, project managers, product owners, designers, your incompetent manager and of course you need to know your customers both internal and external. 

You need to how to review code without making enemies and how to handle criticism, rejection, and derision without flipping tables. You need to know when to stand your ground, when to say no, when to admit you made a mistake, when to let the other guy win.

You need to know when to quit your job and look for something that makes you happier. 

### You

You need to know how to keep up on all the additions and improvements being made to these technologies on a daily basis. You need to know how to teach yourself, how to use google and stack overflow, which blogs are worth reading, which conferences are worth attending, and which books are worth buying. You need to know how to manage your time, how to tell when you are being overworked, when you need a break, and when you can put in more. 

You need to know to never give up, never stop being curious, never stop coding.
